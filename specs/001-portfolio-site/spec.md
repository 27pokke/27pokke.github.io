# Feature Specification: 27pokke Portfolio Site

**Created**: 2026-11-01

**Status**: Draft

**Input**: User description: "ポートフォリオサイトを作りたい。Spec Kit の導入からサイト制作・Pages 公開まで進める。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ひと目で人物像を理解する (Priority: P1)

訪問者は最初の画面で、ぽっけ / 27pokke が東京を拠点にするソフトウェア開発者であることと、
どのような姿勢でものづくりに取り組んでいるかを短時間で理解できる。

**Why this priority**: ポートフォリオの中心価値は、誰のサイトかを迷わず理解してもらうことにあるため。

**Independent Test**: 初めて訪れた人にページ上部だけを見せ、名前、職種、拠点、次に取れる行動を
説明できれば、このストーリーは単独で成立する。

**Acceptance Scenarios**:

1. **Given** 訪問者がトップページを初めて開く, **When** 最初の表示領域を見る,
   **Then** 名前、開発者としての役割、東京拠点であることが確認できる。
2. **Given** 訪問者が詳しい情報を探している, **When** ページ上部を見る,
   **Then** 作品一覧またはプロフィールへ進む明確な導線が見つかる。
3. **Given** アニメーションを減らす設定の利用者が訪問する, **When** ページを閲覧する,
   **Then** 情報を失うことなく落ち着いた状態で内容を読める。

---

### User Story 2 - 公開プロジェクトを探索する (Priority: P2)

訪問者は公開プロジェクトの目的や現在の位置づけを比較し、興味を持ったリポジトリへ移動できる。

**Why this priority**: 実際の制作・学習内容を示すことが、開発者としての関心と取り組みを最も具体的に伝えるため。

**Independent Test**: 作品セクションだけを確認し、各作品の名前、概要、主な技術またはテーマ、
公開先を識別できれば単独で成立する。

**Acceptance Scenarios**:

1. **Given** 訪問者が作品セクションへ移動した, **When** 一覧を見る,
   **Then** 少なくとも3件の公開活動を、それぞれ異なる概要とともに確認できる。
2. **Given** 訪問者が特定の作品に興味を持った, **When** 作品リンクを選ぶ,
   **Then** 対応する公開リポジトリへ移動できる。
3. **Given** 作品が学習中または構想段階である, **When** 作品説明を読む,
   **Then** 完成済みと誤認しない表現で現在の位置づけが分かる。

---

### User Story 3 - さらに知る・つながる (Priority: P3)

訪問者は GitHub または X を通じて、ぽっけの継続的な活動を確認できる。

**Why this priority**: メールアドレスを公開せず、既に本人が公開している経路で次の接点を提供できるため。

**Independent Test**: ページ末尾または固定ナビゲーションから、GitHub と X の本人アカウントへ
迷わず移動できれば単独で成立する。

**Acceptance Scenarios**:

1. **Given** 訪問者がページ末尾まで読んだ, **When** 次の行動を探す,
   **Then** GitHub と X への明示的なリンクを見つけられる。
2. **Given** 訪問者がキーボードのみを使用する, **When** 主要リンク間を移動する,
   **Then** 現在位置を視覚的に確認しながら全リンクを操作できる。

---

### User Story 4 - 端末を問わず快適に読む (Priority: P4)

訪問者はスマートフォン、タブレット、デスクトップのどれからでも、拡大や横スクロールに頼らず
同じ内容を読み、主要リンクを操作できる。

**Why this priority**: ポートフォリオは閲覧環境を選べない公開ページであり、読めること自体が信頼につながるため。

**Independent Test**: 幅320pxから広いデスクトップまで代表的な表示幅で、欠落、重なり、
意図しない横スクロールがないことを確認できれば単独で成立する。

**Acceptance Scenarios**:

1. **Given** 幅320pxの画面でページを開く, **When** 全セクションを閲覧する,
   **Then** 内容の欠落や意図しない横スクロールなしで読める。
2. **Given** 広いデスクトップ画面でページを開く, **When** 全セクションを閲覧する,
   **Then** 行長と余白が読みやすく保たれ、内容が過度に引き伸ばされない。

### Edge Cases

- 外部リンク先が一時的に利用できない場合でも、ページ自体のプロフィールと作品説明は読める。
- スクリプトが読み込めない場合でも、全セクションと主要リンクは利用できる。
- 長い日本語・英語のプロジェクト名やURLがあっても、カードからはみ出さない。
- 高コントラスト設定、200%拡大、文字サイズ拡大でも主要内容と操作が失われない。
- 外部アバター画像が読み込めない場合でも、名前と役割で本人を識別できる。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ページ MUST ぽっけ / 27pokke の名前、ソフトウェア開発者という役割、東京拠点を明示する。
- **FR-002**: ページ MUST 自己紹介、制作物、活動への導線を一貫した読み順で提示する。
- **FR-003**: ページ MUST 本人が公開した情報または本人の公開リポジトリで確認できる事実だけを掲載する。
- **FR-004**: ページ MUST 少なくとも3件の公開活動を、名前、概要、位置づけ、公開先とともに掲載する。
- **FR-005**: ページ MUST 学習中・構想中・フォークした活動を、完成済みの独自成果と誤認させない。
- **FR-006**: 訪問者 MUST GitHub プロフィールと X アカウントへ移動できる。
- **FR-007**: 訪問者 MUST ページ内ナビゲーションから主要セクションへ移動できる。
- **FR-008**: すべての主要リンクとナビゲーション MUST キーボードだけで操作でき、フォーカスが視認できる。
- **FR-009**: ページ MUST 幅320px以上の代表的な画面幅で、内容欠落と意図しない横スクロールなく利用できる。
- **FR-010**: ページ MUST 動きを減らす利用者設定を尊重し、動きなしでも同じ情報を提供する。
- **FR-011**: ページ MUST 任意のスクリプトや外部画像が失敗しても、プロフィール、作品説明、主要リンクを提供する。
- **FR-012**: ページ MUST 公開リポジトリの既定ブランチから、追加の手動編集なしに公開可能である。
- **FR-013**: ページ MUST 日本語を主言語とし、技術名やプロジェクト名の英字を自然に併記する。
- **FR-014**: ページ MUST 内容の読みやすさを保つ十分な文字コントラストと明確な見出し階層を持つ。

### Key Entities

- **Profile**: 表示名、ユーザー名、役割、拠点、短い紹介文、公開アカウントへのリンクを持つ人物情報。
- **Project**: 名前、概要、現在の位置づけ、主なテーマまたは技術、リポジトリURLを持つ公開活動。
- **Section**: ページ内ナビゲーションの対象になる、導入、紹介、作品、連絡先の各内容領域。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初見の訪問者が10秒以内に、名前、職種、拠点、主要な次の行動を説明できる。
- **SC-002**: 訪問者が2回以内の操作で、任意の掲載プロジェクトの公開リポジトリへ到達できる。
- **SC-003**: 主要なユーザーシナリオの100%をキーボードだけで完了できる。
- **SC-004**: 幅320px、768px、1440pxの各表示で、内容の欠落、重なり、意図しない横スクロールが0件である。
- **SC-005**: スクリプト無効時にも、プロフィール、全作品説明、GitHub・Xリンクの100%が利用できる。
- **SC-006**: 公開後のトップページが通常のモバイル回線で3秒以内に主要内容を表示する。
- **SC-007**: 掲載する人物・作品の記述が、公開情報との照合で事実誤認0件となる。

## Assumptions

- 初期版は1ページ構成とし、ブログ、問い合わせフォーム、多言語切替は対象外とする。
- 公開プロフィールの表示名「ぽっけ」、所在地「Tokyo」、自己紹介
  「Software developer based in Tokyo, Japan.」を本人の公開情報として扱う。
- 連絡導線には公開済みの GitHub `27pokke` と X `27pokke` を使用し、メールアドレスは掲載しない。
- 作品には、本人のプロフィール自動化、Laravel DDD Practice、kataribe を中心に掲載し、
  必要に応じて Danger SwiftLint への公開上の関与を明確な注記付きで補足する。
- GitHub Pages はこのユーザーサイト用リポジトリの既定ブランチを公開元として利用する。
